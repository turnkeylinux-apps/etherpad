# Etherpad 19.0 testing

## Scope and dependency decision

Debian 13 Trixie provides Node.js 20, while supported Etherpad 3.x requires
Node.js 24 or later. Etherpad 19.0 therefore installs the current Etherpad
stable package from the project's signed APT repository and Node.js 24 from
NodeSource's signed repository. The build verifies the exact repository key
fingerprints before APT accepts either source. MariaDB, nginx, Postfix and the
remaining system integration come from signed Debian Trixie repositories.

This retains the normal Debian update workflow:

```sh
apt update
apt upgrade
```

Etherpad's package preserves `/etc/etherpad/settings.json` during upgrades.
TurnKey configures that file for MariaDB, HTTPS proxy awareness and the
firstboot administrator account.

## Acceptance command

```sh
/sandboxed-git/turnkey/tools/test-v19-appliance etherpad \
    --source /home/agent/.local/worktrees/turnkey-apps/etherpad/wish-etherpad-v19-trixie
```

The retained run identifier and evidence digest are recorded here after the
exact committed candidate passes.

Before the appliance build, a disposable Trixie container installed Etherpad
3.3.3 and Node.js 24.19.0 from the same signed repositories. Its focused
preflight started Etherpad, created a pad through the HTTP API, wrote text and
read the same text back. It also verified successful administrator
authentication and rejected an incorrect password.

## Deferred issues

- The v18 appliance bundled several optional editor plugins. They are not part
  of the primary README contract and are deferred until the Etherpad 3.3.3
  collaboration, persistence and administrator flows pass end to end.
- Office document import and export require LibreOffice, which remains an
  optional installation because of its image size. The README documents the
  administrator command and configuration path.
- Outbound email delivery depends on site-specific relay and DNS settings, so
  the focused test covers Postfix supervision and its loopback listener.
